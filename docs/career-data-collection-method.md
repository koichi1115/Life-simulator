# 職業データ収集方法

## 1. 概要

本ドキュメントでは、子供向け職業シミュレータのために、世界中のあらゆる職業（違法なものを除く）を漏れなく収集する手法を定義します。

### 対象範囲
- ✅ 現存する全ての合法的な職業
- ✅ 近い将来（5年以内）誕生することが確実な職業
- ❌ 現存しない架空の職業
- ❌ 違法な職業

### 収集すべきデータ項目
各職業について以下の情報を収集します：
- 職業名（多言語対応）
- 職業の説明
- 従事者数（国/地域別）
- 平均年収（国/地域別）
- 必要な学歴・資格
- 必要なスキル
- 就業までのキャリアパス
- 関連する業界・分野
- 将来性（需要予測）

## 2. 職業分類の国際標準

職業を体系的に収集するため、国際的に認められた職業分類システムを基準とします。

### 2.1 ISCO（International Standard Classification of Occupations）
**国際労働機関（ILO）による国際標準職業分類**

- **最新版**: ISCO-08（2008年版、定期的に更新）
- **構造**: 10大分類 → 43中分類 → 130小分類 → 436細分類
- **取得方法**: ILO公式サイト（https://www.ilo.org/public/english/bureau/stat/isco/）
- **メリット**: 世界共通の分類で、国際比較が可能
- **デメリット**: 更新頻度が低く、新興職業の反映が遅い

#### ISCO-08 大分類（10カテゴリ）
1. 管理職
2. 専門職
3. 技術職および準専門職
4. 事務補助職
5. サービス・販売職
6. 農林漁業の熟練従事者
7. 技能工およびその関連職
8. 設備・機械の運転・組立工
9. 単純作業の職業
0. 軍隊

### 2.2 O*NET（Occupational Information Network）
**米国労働省による職業情報データベース**

- **最新版**: 継続的に更新（年2回）
- **規模**: 約1,000職業を詳細にカバー
- **取得方法**:
  - O*NET Online（https://www.onetonline.org/）
  - O*NET API（https://services.onetcenter.org/）
- **メリット**:
  - 詳細なスキル情報、給与データ、将来性予測
  - 定期的な更新
  - APIで自動取得可能
- **デメリット**: 米国中心のデータ

### 2.3 各国の職業分類
各国が独自の職業分類を持っており、地域特性を反映しています。

#### 日本
- **日本標準職業分類**: 総務省統計局
- **厚生労働省職業分類**: ハローワークで使用
- **取得先**: https://www.stat.go.jp/index/seido/shokgyou/

#### EU
- **ESCO（European Skills, Competences, Qualifications and Occupations）**
- **取得先**: https://esco.ec.europa.eu/

#### その他主要国
- **カナダ**: NOC（National Occupational Classification）
- **オーストラリア**: ANZSCO（Australian and New Zealand Standard Classification of Occupations）
- **英国**: SOC（Standard Occupational Classification）
- **中国**: 中国職业分类大典

#### グローバル
- Indeed（https://www.indeed.com/）

- Glassdoor

#### 地域別
- **日本**: リクナビ、マイナビ、doda、ビズリーチ

**データ取得方法**:
- 公開API（提供されている場合）

- データパートナーシップ契約

### 3.4 業界団体・専門協会

各業界の専門協会は、最新の職業情報を持っています。

#### 主要な業界団体の例
- **医療**: 世界医師会、各国医師会、看護協会
- **法律**: 国際法曹協会、各国弁護士会
- **エンジニアリング**: IEEE、各国技術士会
- **会計**: IFAC（国際会計士連盟）、AICPA
- **教育**: UNESCO、各国教員組合
- **芸術**: 各国芸術家協会、映画協会、音楽家協会

**取得方法**:
1. 協会公式サイトから職業リスト取得
2. 会員向けキャリア情報の参照
3. 資格・認定制度から職業の特定

### 3.5 教育機関データ

大学・専門学校のカリキュラムから、それに対応する職業を特定できます。

**データソース**:
- 大学のキャリアセンター情報
- 専門学校の就職実績
- オンライン教育プラットフォーム（Coursera、edX）のキャリアパス情報

## 4. データ収集手法

### 4.1 段階的アプローチ

#### フェーズ1: ベースライン構築（1-2ヶ月）
1. **国際標準分類の取得**
   - ISCO-08の全カテゴリ（約430職業）をダウンロード
   - O*NET データベース（約1,000職業）をAPIで取得
   - 各国の職業分類（主要10カ国）を収集

2. **データ統合**
   - 重複職業の名寄せ
   - 職業の階層構造の整理
   - 初期データベーススキーマの設計

**成果物**: 基本的な職業リスト（推定1,500〜2,000職業）

#### フェーズ2: 詳細データ拡充（2-3ヶ月）
1. **統計データの収集**
   - ILO、OECD、各国統計局から従事者数データ取得
   - 給与データの収集（BLS、PayScale、Glassdoor等）

2. **教育・資格要件の収集**
   - 各職業に必要な学歴・資格をマッピング
   - 教育機関データとの連携

3. **多言語対応**
   - 主要言語（英語、日本語、中国語、スペイン語等）への翻訳
   - 地域固有の職業名の収集

**成果物**: 詳細情報付き職業データベース

#### フェーズ3: 新興職業の追加（継続的）
1. **トレンド分析**
   - 求人サイトでの新規職業名の出現監視
   - 業界レポートのスキャン
   - ニュース・メディアの職業関連記事分析

2. **専門家ヒアリング**
   - 業界リーダーへのインタビュー
   - 未来予測レポートの参照

**成果物**: 継続的に更新される職業データベース

### 4.2 自動化戦略

#### APIベースの自動収集
```
推奨ツール:
- Python + requests/httpx（API呼び出し）
- Scrapy/Beautiful Soup（Webスクレイピング）
- Pandas（データ処理）
- PostgreSQL/MongoDB（データ保存）
```

#### 収集スクリプトの実装項目
1. **O*NET API統合**
   - 職業リストの定期取得（週次）
   - 差分更新の自動検出

2. **統計データの自動取得**
   - ILOSTATのCSVダウンロード自動化
   - BLS APIの統合

3. **Webスクレイピング**
   - 求人サイトの職業カテゴリ抽出
   - robots.txt遵守
   - レート制限の実装

### 4.3 データ品質管理

#### 検証プロセス
1. **重複チェック**
   - 職業名の類似度計算（Levenshtein距離等）
   - 同義語・表記揺れの統合
   - 職務内容の類似性分析

2. **データ完全性チェック**
   - 必須項目の欠損チェック
   - 数値データの妥当性検証（例: 給与が異常値でないか）
   - 外れ値の検出と修正

3. **定期的な更新**
   - 四半期ごとの統計データ更新
   - 年次での職業リストの全面見直し

#### データソースの信頼性評価
| レベル | 基準 | 例 |
|-------|------|---|
| 最高 | 公的機関の公式統計 | ILO、各国政府統計局 |
| 高 | 業界団体の公式データ | 専門協会、認定機関 |
| 中 | 商業データベース | Glassdoor、PayScale |
| 低 | クラウドソース | Wikipedia、個人ブログ |

## 5. 将来誕生する職業の特定方法

### 5.1 対象となる将来職業の定義
- **時間軸**: 5年以内に誕生する可能性が高い
- **確実性**: 業界レポートや専門家が言及している
- **実現性**: 技術的・社会的に実現可能

### 5.2 情報ソース

#### 1. 未来予測レポート
| 発行元 | レポート名 | 頻度 | URL |
|-------|----------|-----|-----|
| World Economic Forum | Future of Jobs Report | 隔年 | https://www.weforum.org/ |
| McKinsey | Workforce Trends | 不定期 | https://www.mckinsey.com/ |
| Gartner | Top Strategic Technology Trends | 年次 | https://www.gartner.com/ |
| LinkedIn | Emerging Jobs Report | 年次 | https://economicgraph.linkedin.com/ |

#### 2. テクノロジートレンド
- **AI/ML**: AIトレーナー、プロンプトエンジニア、AI倫理コンサルタント
- **環境**: カーボンニュートラルコンサルタント、リワイルディング専門家
- **医療**: 遺伝子カウンセラー、遠隔医療コーディネーター
- **宇宙**: 宇宙旅行コーディネーター、小惑星採掘エンジニア
- **メタバース**: バーチャル空間デザイナー、デジタルファッションデザイナー

#### 3. 規制・政策の変化
- 新しい法律や規制により生まれる職業
  - 例: データ保護オフィサー（GDPR施行後）
  - 例: ドローン操縦士（ドローン規制整備後）

#### 4. 社会変化
- 高齢化社会: 高齢者向けテックサポート、介護ロボットメンテナンス
- リモートワーク: リモートチームビルダー、バーチャルイベントプロデューサー

### 5.3 将来職業の検証基準
以下の3つの基準を満たす場合のみ収集対象とする：

1. **実現性**: 現在の技術・社会で実現可能か
2. **需要**: 複数の信頼できる情報源が言及しているか
3. **具体性**: 職務内容が明確に定義できるか

## 6. データ構造設計

### 6.1 職業マスターテーブル

```sql
CREATE TABLE occupations (
  occupation_id UUID PRIMARY KEY,
  occupation_name VARCHAR(255) NOT NULL,
  occupation_code_isco VARCHAR(10),  -- ISCO-08コード
  occupation_code_onet VARCHAR(10),  -- O*NETコード
  occupation_code_local VARCHAR(20), -- 各国の職業分類コード
  category_major VARCHAR(100),       -- 大分類
  category_minor VARCHAR(100),       -- 中分類
  description TEXT,                  -- 職業の説明
  is_future_occupation BOOLEAN,      -- 将来職業フラグ
  estimated_emergence_year INT,      -- 誕生予測年
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);
```

### 6.2 多言語対応テーブル

```sql
CREATE TABLE occupation_translations (
  translation_id UUID PRIMARY KEY,
  occupation_id UUID REFERENCES occupations(occupation_id),
  language_code VARCHAR(5),  -- ja, en, zh, es等
  name VARCHAR(255),
  description TEXT,
  PRIMARY KEY (occupation_id, language_code)
);
```

### 6.3 統計データテーブル

```sql
CREATE TABLE occupation_statistics (
  stat_id UUID PRIMARY KEY,
  occupation_id UUID REFERENCES occupations(occupation_id),
  country_code VARCHAR(3),   -- ISO 3166-1 alpha-3
  year INT,
  employed_count BIGINT,     -- 従事者数
  avg_salary_usd DECIMAL,    -- 平均年収（USD換算）
  avg_salary_local DECIMAL,  -- 平均年収（現地通貨）
  currency_code VARCHAR(3),
  data_source VARCHAR(255),  -- データソース
  source_url TEXT
);
```

### 6.4 教育要件テーブル

```sql
CREATE TABLE education_requirements (
  requirement_id UUID PRIMARY KEY,
  occupation_id UUID REFERENCES occupations(occupation_id),
  education_level VARCHAR(50),  -- 高卒、大卒、修士、博士等
  required_certifications TEXT[], -- 必要な資格（配列）
  required_skills TEXT[],        -- 必要なスキル（配列）
  typical_career_path TEXT       -- 典型的なキャリアパス
);
```

## 8. 考慮すべき課題と対策

### 8.1 課題

#### 1. データの不均質性
**課題**: 国や地域によってデータの詳細度が異なる
**対策**:
- データ品質レベルの定義
- 最低限必要な情報項目の設定
- 段階的なデータ拡充

#### 2. 職業の粒度
**課題**: 「医師」という大きなカテゴリと「小児心臓外科医」という細かいカテゴリをどう扱うか
**対策**:
- 階層構造の導入（大→中→小）
- 子供向けには大分類、詳細情報として小分類を提供

#### 3. 文化的差異
**課題**: 同じ職業でも国によって仕事内容や地位が異なる
**対策**:
- 国/地域別のデータ保持
- グローバル共通の説明 + 地域特有の補足情報

#### 4. 更新頻度
**課題**: 職業情報は常に変化する
**対策**:
- 自動更新パイプラインの構築
- データソースごとの更新スケジュール管理
- バージョン管理システムの導入

### 8.2 データの正確性確保

#### 検証方法
1. **クロスチェック**: 複数のデータソースで同じ職業の情報を照合
2. **専門家レビュー**: 業界専門家による定期的な監査
3. **ユーザーフィードバック**: システム利用者からの情報提供
4. **統計的検証**: 異常値や外れ値の自動検出

## 9. 法的・倫理的考慮事項

### 9.1 著作権・ライセンス
- 公的統計データ: 通常は自由に利用可能（出典明記）
- 商業データベース: ライセンス契約が必要
- Webスクレイピング: 利用規約の確認必須

### 9.2 プライバシー
- 個人を特定できる情報は収集しない
- 統計データのみを使用

### 9.3 子供向けコンテンツとしての適切性
- 職業の説明は子供に理解できる言葉で
- ネガティブな側面（例: 危険性）も適切に伝える
- 職業に対する偏見を助長しない表現
